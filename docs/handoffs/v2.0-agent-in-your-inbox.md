# v2.0 "Agent in your inbox" — Handoff

## Outcome

- Result: All 16 milestone issues (#97–#112) implemented, tested, and documented.
- User-visible effect: The bot now writes full natural-language replies (no deterministic templates), uses progressive disclosure (compact core prompt + on-demand capability docs), supports weekly summaries, food-history search, and user-scoped custom food aliases. Tool modules are split into focused files with a central registry.
- Status: complete — ready for user's final review before merging v2.0 into master.

## Scope and decisions

- In scope: Issues #97–#112 (all v2.0 milestone issues).
- Out of scope: Dynamic tool routing (deferred to post-v2.0 per ADR 0007). Java sister repository (independent build path). Live OpenAI eval runs (require API budget and isolated DB; fixture structure is validated by unit tests).
- Key decisions:
  - Progressive disclosure: core prompt (~15 lines) + 7 capability markdown docs loaded via `load_instructions(topic)`.
  - Model writes full replies from structured tool results; deterministic templates removed.
  - `context.romanian` removed; model decides language.
  - Tool modules split: `journal_actions.py`, `nutrition.py`, `planning.py`, `settings.py`, `instructions.py`, `aliases.py`, `shared.py`, `registry.py`.
  - Food aliases use a stored generated column (`alias_lower = lower(alias)`) for case-insensitive uniqueness with atomic ON CONFLICT upsert.
  - Adversarial review findings B1, H1, H2, H3, M1, L1, L2 fixed; M2 (broad transaction pattern) fixed with an inbox savepoint and retry-state-preserving outer transaction.
- Assumptions:
  - The dev/test database is the only environment with applied migrations; production will receive migrations through `d5e6f7a8b9c0` in sequence.
  - The eval fixture file (`text-journal.json`) is the authoritative scenario list; live model eval is run manually with `TERMINAL_EVAL_FILE`.

## Adversarial review

- Cases attempted: ownership isolation, case-variant duplicates, non-string args, boolean calories, control characters in canonical name, overly long strings, empty/missing fields, out-of-range calories, mutual exclusion of calorie fields, cross-user resolve.
- Findings:
  - B1 (blocker): Case-sensitive unique constraint allowed case-variant duplicates → FIXED with generated column + case-insensitive constraint.
  - H1 (high): Non-atomic upsert race condition → FIXED with ON CONFLICT upsert.
  - H2 (high): No string type/length validation → FIXED with isinstance check and length limits.
  - H3 (high): Boolean calories accepted → FIXED with explicit bool rejection.
  - M1 (medium): No DB-level check constraints → FIXED with CHECK constraints in migration.
  - L1 (low): No schema string length limits → FIXED with minLength/maxLength in tool schemas.
  - L2 (low): Control characters in canonical name → FIXED with regex validation.
  - M2 (medium): Broad transaction commit pattern in inbox_worker → FIXED with a savepoint around business work and an outer transaction for inbox retry state.
- Regression coverage added: 5 new adversarial tests in test_food_aliases.py (non-string alias, boolean calories, control characters, overly long alias, case-variant duplicate prevention).
- Residual risks:
  - Unexpected business failures roll back the savepoint before the inbox retry is committed; conversation-memory and provider-neutral status failures are isolated in nested savepoints so they do not replay journal mutations. Strictly malformed persisted payloads are marked terminal instead of retried.
  - Journal mutations and Undo serialize on the verified user row; Undo also locks owned entries and compares their complete current snapshot with the recorded post-mutation state before restoring.
  - Positive quantity, derived-calorie, and alias shortcut limits are enforced both in runtime handlers and tool schemas; oversized packaged/estimate quotes are not persisted.
  - Live model eval not run: The eval fixture structure is validated by unit tests, but live OpenAI calls require an API budget and isolated database. Run `TERMINAL_EVAL_FILE='app/terminal/fixtures/text-journal.json' TERMINAL_EVAL_REPEATS=3 python -m app.terminal.repl` manually before production release.
  - L3: `list_by_user` in food_alias_repo is currently unused; kept for future use.

## Review fixes (post-handoff)

Review issues found during review and fixed:

1. **`load_instructions` enum missing `aliases`**: The system prompt advertised an `aliases` capability index entry, but the `load_instructions` tool's `topic` enum did not include `"aliases"`, so the OpenAI API would reject any `load_instructions(topic="aliases")` call. Added `"aliases"` to the enum in `tool_schemas.py` and added a regression test.
2. **`portions.md` referenced non-existent `compute_portion` tool**: The portions capability doc told the model to use a `compute_portion` tool that does not exist in the registry or tool definitions, which would cause production failures when the model tried to call it. Rewrote `portions.md` to instruct the model to compute fractions itself with basic arithmetic. Updated `test_load_instructions.py` to assert the doc does not reference unknown tools.
3. **Dead `is_romanian` import**: Removed the unused `from app.agent.language import is_romanian` import from `journal_application_service.py` (the function is still defined in `app/agent/language.py` for future use, but no longer imported in the service).
4. **Unexpected failures could commit partial work**: Added strict tool-argument validation, propagated unexpected tool failures, and wrapped inbox business work in a savepoint so only the retry state commits after rollback.
5. **Provider failure could hide a successful mutation**: Added a minimal receipt fallback from the server-owned structured action result and regression coverage preventing duplicate retries.
6. **Fallback receipt could become stale after Undo**: Made fallback rendering account for later successful Undo results and aggregate still-active successful mutation batches.
7. **Malformed model arguments could reach database limits**: Added bounded text, identifier, numeric, and control-character validation and aligned the function schemas with those limits.
8. **Settings validation could partially mutate state**: Validate all requested settings before applying any update.
9. **Cross-frontend daily-status refresh could reject Mattermost channel IDs**: The Telegram-only pinned-status adapter now ignores opaque non-Telegram chat IDs; Undo also refuses to mark a change set undone when any mutation cannot be resolved safely.
10. **Tool contract/runtime drift at numeric boundaries**: Positive quantity constraints are reflected in schemas, CREATE accepts the schema-permitted zero-calorie value, and oversized derived nutrition totals are rejected before quote persistence or journal mutation.
11. **Undo could overwrite an intervening change**: Mutating entry reads are locked and Undo compares the complete current snapshot with the recorded post-mutation snapshot before restoring.
12. **Malformed persisted inbox payloads could consume retries**: Deserialization failures are classified as terminal inbox failures and the payload is cleared without retrying.
13. **Planning and read/external tool arguments were under-bounded**: Runtime text validation now rejects non-string, oversized, and control-character values, with matching schema limits.
14. **Persisted inbox payloads could deserialize with unsafe field types**: Provider, identifiers, optional text fields, and attachments are now strictly validated before processing; invalid payloads are terminal failures.
15. **Concurrent journal mutation could make Undo select an older change**: Journal mutations and Undo now serialize on the verified user row before selecting or creating a change set.
16. **Alias numeric schema bounds drifted from runtime validation**: `save_alias` calorie shortcut schemas now expose the same 1–10000 and 0–10000 bounds enforced by the handler.
17. **Post-journal bookkeeping could replay committed mutations**: Conversation memory and provider-neutral daily-status updates now run in independent nested savepoints, with regression coverage confirming the inbox completes and the mutation persists once when either fails.
18. **Undo expiry could surface as a retryable exception**: Undo validates the window before mutation, converts expiry races to a handled `NOT_FOUND`, and wraps the operation in a rollback-safe savepoint.
19. **Media-derived prompt content could be duplicated**: The model user-content builder now includes transcript, interpretation, and captions only once.
20. **Legacy gram quantities could become null on new rows**: Gram journal items and restored snapshots now populate both `quantity_grams` and generic quantity fields.
21. **External URL validation blocked the event loop and allowed unsafe ports**: DNS checks are moved off the event loop, non-web ports and credential-bearing URLs are rejected, and every redirect hop is revalidated.
22. **Quote-only CREATE behavior was inconsistent**: A selected server quote can supply the description, with runtime coverage and an updated tool contract.
23. **SSRF validation stopped before the actual Browserless navigation**: Browserless now revalidates immediately, disables JavaScript navigation, narrows navigation to the validated hostname, and requires deployment-level egress restrictions.
24. **Undo could use an old request timestamp**: Undo expiry checks now use execution time rather than `AgentContext.started_at`.
25. **Media provenance labels could disappear during deduplication**: The model content builder replaces the worker-injected leading transcript/interpretation with one labelled server note.
26. **Provider failure could hide durable non-journal work**: Fallback acknowledgements now cover pending nutrition choices, saved foods, aliases, and settings.
27. **Persisted inbox and provider payloads lacked complete bounds**: Inbox payload size, field lengths, attachment count, and parser failure classification are bounded; external nutrition strings are validated before persistence.
28. **Optional pinned-status bookkeeping could replay journal work**: Pinned daily-status refresh now runs in an independent savepoint and cannot turn a committed mutation into an inbox retry.
29. **Mattermost identifiers exceeded the initial ingress bound**: Provider-neutral external IDs now accept real 26-character Mattermost IDs while retaining a finite safety limit.
30. **Link-code redemption could race**: Redeem locks the code row and consume is guarded by the same expiry/consumed check.
31. **Schema/runtime positive-number drift**: The shared decimal validator now supports and enforces exclusive lower bounds at the call sites that require positive quantities.
32. **DNS rebinding during redirect probes**: Public DNS results are pinned to the per-request HTTP transport; Browserless is fail-closed unless the deployment explicitly opts in with a restricted-egress setting and filtering proxy.
33. **Database-scale quantity drift**: Quantities must be representable at the journal's two-decimal storage precision, with matching `multipleOf` schema bounds.
34. **Provider calorie bounds**: Packaged quotes and selected persisted quotes reject calories outside the 1–10000 kcal/100 g range.
35. **Fallback aggregation after Undo**: Durable non-journal acknowledgements are combined with Undo and later journal receipts instead of being dropped.
36. **Mutation Undo deadline timestamp**: Change-set creation and all mutation receipts use execution time, while meal-date interpretation remains anchored to request time.
37. **Live ingress payloads could bypass persistence bounds**: Inbound messages are now validated and serialized-size checked before `messaging_inbox` insertion; invalid live messages are acknowledged without persistence.
38. **Deep or oversized model arguments could trigger retryable parser failures**: Tool-call JSON is bounded before parsing and recursion failures are returned as validation errors.
39. **Browserless egress was only self-attested**: Browserless now requires an explicit operator-controlled filtering proxy in addition to the restricted-egress opt-in and passes it on every navigation request.
40. **Review follow-ups**: Telegram link codes are private-chat-only; concurrent redemption verifies the winning identity owner; inbox receipt timestamps survive queue delays; final inbox commits recover retry state; packaged Open Food Facts search uses the shared 1–10000 kcal/100 g bound.

Additionally cleaned up 30 unused imports and 2 nested-if style issues across the v2.0 tool modules (pre-existing leftovers from the refactor) via `ruff --fix` and manual edits. Restored `_resolve_meal_instant` as a re-export in `journal_tool_executor.py` with `# noqa: F401` because tests import it from that module.

Final verification: 130 unit tests + 102 integration tests pass (232 total), `ruff check app tests` clean.
